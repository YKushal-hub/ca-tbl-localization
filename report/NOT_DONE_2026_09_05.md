## The blocker, and the correction to what it was thought to cost

`EnginePhyProvider` held one `m_nodeId` and one `m_nodePos` and returned early from
`Evaluate()` for any frame with neither endpoint equal to it. Because it sits **below**
the MAC, that early return was invisible above: a peer tag's frames counted as sent, lost
nothing to duty, CAD or collision, and were never delivered.

**Fixed 2026-09-05** (`3c95a86`, pre-registered at `ede157f`). The provider now carries a
position per field node. Null control: **all seven** `baseline_v7` digests reproduce,
`arm_summary.csv` and all six traces, using that baseline's own recorded invocation.

**This register previously claimed the fix required C2-full. That was wrong.** The
engines were already multi-node — `m_nodeStates` is a map and peers were already
`RegisterNode()`d and `UpdateNodePosition()`d on all three — so the only single-node
component was the provider. The scope had been inferred from the instrumentation rather
than read off the engine's data structures. Full account, including the wrong inference:
`report/C4_PROVIDER_BLOCKER.md`.

## Two claims this register made that are now withdrawn

**1. The dedup cache cannot distinguish two nodes — WITHDRAWN, the defect does not
exist.** This register recorded that `NextPacketId()` returns a per-MAC counter starting
at 0, so two nodes' packet ids would collide in a cache keyed on packet id alone. That is
false: `CaTblMac::Configure` sets `m_packetIdCounter = nodeId << 20`, and `Reset()`
re-seeds it identically (`ca-tbl-mac.cc:142`, `:162`), with a comment saying exactly why.
Each node has a 2^20 id space. The claim was written from reading `NextPacketId()` alone
without reading its initialiser. **Nothing needs fixing here.**

**2. Any addition to `RunArm` perturbs the codegen — WITHDRAWN, too strong.** This
register explained the 1-ulp trace divergence on the C2/C3/C4 branches by asserting that
*any* addition to `RunArm` changes the stack frame and therefore what the compiler emits
under `-march=native`. The provider fix grew a `RunArm` stack local by a `std::map` and
**all six traces are byte-identical**. Whatever causes the divergence on those branches,
it is not the mere fact of touching the frame — which means it is worth diagnosing rather
than accepting, and the C3/C4 merge decision should not be made on the assumption that it
is unavoidable.

### C5 — hop-provenance — PARTIAL, and the stopping point is deliberate
The error model is written (`docs/RELAYED_RANGING_ERROR_MODEL.md`) and the **admission
layer is built and gated**: A1–A5 plus the covariance inflation
`sigma_eff^2 = sigma_range^2 + u^T P_B u`, with **G15 and five negative fixtures, each
condition observed to reject under its own verdict**. Null control byte-identical;
nothing in `ca_tbl_causal_sim.cc` changed.

**Not done, and the reason is a real cost rather than a shortage of time.** Feeding
admitted measurements to the filter requires the relay to transmit its covariance, which
serialises three doubles, which **changes airtime and therefore energy**. At that point
the §6 invariant — exactly one tier transmits per cycle, and only that tier is charged —
has to be re-established rather than assumed, and the error model names that as the first
thing to check in review of the step. The admission layer is complete and testable without
touching what goes on the air; continuing would have put the energy axis at risk in order
to add a consumer that is not yet tested.

The older framing, kept because it is still true of the remainder:
`hopWeight` stays 0: a non-zero weight on a hop count that is structurally always zero
changes nothing, and applied to an admitted-but-unreachable peer it degrades the score for
an **energy** defect rather than a provenance one.

**Tag-to-tag links are the concrete blocker under C5** and are deliberately left
unevaluable. They are reachable — `ProcessTransmission` auto-registers an unknown receiver
as a gateway with `fineTimestamp=false`, the correct hardware class for a tag — but a
tag-to-tag range enters the solution as a *relayed* measurement, and without the error
model nothing is entitled to weight it. Enabling the link first would produce ranges that
look usable and are not attributable.
