# PREREG ML-PATHLOSS — a learned 868 MHz distance estimator against classical inversion, on real measurements

Registered 2026-10-21, before any model is fitted. Script: `scripts/pathloss_ml_bonn.py`, committed with this file
and not edited after the first run.

## 1. Question

The 868 MHz tier turns RSSI into a range by inverting a log-distance path-loss model. Its error is a factor, not a
distance: ×/÷4.23 at one sigma with the Rademacher fit (n = 1.58, σ = 9.9 dB). The proposal under test is to
replace the inversion with a machine-learned regressor (proposal list, "Adaptive / ML path loss modelling").

Inside the simulator the question is circular: RSSI there is generated by the simulator's own path-loss formula, so
a model trained on it relearns that formula. It is therefore tested on **real** measurements.

## 2. Data

Rademacher et al. 2021 (VTC2021-Fall; arXiv:2109.07768), `github.com/mclab-hbrs/lora-bonn`, files
`survey/samples.csv` and `survey/gateways.csv`:
- 868 MHz LoRa packets from GPS sensors on garbage trucks in Bonn, received by city gateways;
- each packet has latitude, longitude, date, RSSI, SNR and gateway id;
- each gateway has a surveyed position.

The data are licensed under Data licence Germany – attribution – 2.0 and are not copied into this repository.

**Truth:** the horizontal haversine distance from the packet's GPS fix to the gateway. Packets closer than 10 m are
dropped.

## 3. Models

All models predict log10 d from a single packet, as the tier does per range.

| model | form | parameters |
|---|---|---|
| C1 | global log-distance fit, RSSI = a + b·log10 d, inverted | 2 |
| C2 | the same, per gateway | 2 per gateway |
| C3 | per-gateway inverse regression, log10 d = c + k·RSSI | 2 per gateway |
| C4 | per-gateway inverse regression on RSSI and SNR | 3 per gateway |
| ML | gradient-boosted trees (`HistGradientBoostingRegressor`, 300 iterations, learning rate 0.1, random_state 20261021) on RSSI, SNR and gateway (categorical) | many |

- **Small gateways.** A gateway with fewer than 50 training packets falls back to the global fit.
- **Date excluded from the features.** Garbage trucks follow fixed routes on fixed days, so the date would leak
  location.
- **SF not a feature.** Spreading factor is not in the data.
- **C3 and C4 isolate what ML adds.** Any gain from regressing in the inverse direction, or from adding SNR, is
  credited to a linear model first.

## 4. Evaluation

- **Primary: spatially blocked 5-fold cross-validation.**
  - Packets are binned into 1 km × 1 km blocks on a local equirectangular projection.
  - Blocks are assigned to folds at random (NumPy seed 20261021).
  - No test packet's block is seen in training.
  - This reflects the use case: a lost node is somewhere nobody surveyed.
- **Metrics:**
  - the median and 68th-percentile multiplicative error factor 10^q(|log10 d̂ − log10 d|);
  - the median absolute error;
  - the mean absolute log10 error, which is the test statistic.
- **Comparison:** ML against the best classical model, meaning the C1–C4 model with the lowest mean absolute
  log10 error. That model is chosen on the test predictions, which favours the classical side, so the comparison is
  conservative against ML.
- **Interval:** 95 % cluster bootstrap over blocks (10 000 resamples) of the per-packet difference
  |e_ML| − |e_best|.

**Verdict:**
- **HELPS** if the interval lies below 0 and ML's 68 % factor is at most 0.90 × the best classical one;
- **SMALL** if the interval lies below 0 but the ratio is above 0.90;
- **NO GAIN** otherwise.

A random-packet fold split is also reported as a contrast. It leaks location and is not the registered test.

## 5. Predictions (before fitting)

- **M1.** C3 or C4 beats C1 and C2. Inverse regression is the better estimator of log d under heavy noise.
- **M2.** ML against the best classical model is SMALL or NO GAIN at unseen locations. The error is dominated by
  shadowing that varies from place to place, and no packet feature carries it.
- **M3.** The random-split contrast shows a larger ML advantage than the blocked test does, because the trees
  memorise locations.

## 6. Limitations

- **Urban data.** Bonn is urban, with gateways at a 16 m antenna height and sensors on trucks. CA-TBL's case is
  rural search, with field nodes near the ground. Transfer of the size of any effect is not established.
- **Per packet only.** No temporal tracking and no fusion are tested.
- **Ranging only.** Even a HELPS verdict concerns the 868 MHz tier's ranging alone. The endgame accuracy is set by
  2.4 GHz time of flight, which this does not touch.

## Reading

1. **ML adds nothing.** A three-parameter linear model per gateway matches gradient-boosted trees at unseen
   locations.
2. **What does improve is not ML.** The improvement over the tier's inversion (C1/C2 → C3/C4) comes from regressing
   in the inverse direction. That pulls each estimate toward the training set's distance distribution, here the
   trucks' routes. Its size therefore depends on how far that distribution matches where the lost node actually is.
   It is a prior, not better ranging. CA-TBL's filter already combines each range with its state prior.
3. **None of this touches the endgame**, which is set by 2.4 GHz time of flight (section 6).
