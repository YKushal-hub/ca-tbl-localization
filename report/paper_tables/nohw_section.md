# Options that need no new hardware (paper section draft)

Tables: `nohw_tables.md` / `nohw_tables.tex` (generated by `scripts/paper_tables_nohw.py`). Registrations and
results: `report/PREREG_ORACLE_ESC.md`, `PREREG_ML_PATHLOSS.md`, `PREREG_ML_PATHLOSS_POS.md`,
`PREREG_TDOA_TIMING.md`, `PREREG_TDOA_TIMING_B.md`.

Three proposals improve LoRa localisation without new hardware:
1. a learned confidence input to the escalation decision;
2. a learned 868 MHz path-loss model;
3. better tier-1 arrival timing, through nanosecond gateway synchronisation or two-pass CFO/STO timing refinement.

Each was tested as a **ceiling**, the best any implementation could reach, under a pre-registered design. Each was
run on CA-TBL and on the comparators of Tables 1–2.
- A null ceiling rules an option out for the configuration tested.
- A positive ceiling bounds what an implementation could gain. It does not predict that gain.

## 1. A learned confidence input to escalation (Table 6)

**What was tested.** CA-TBL and Fixed threshold both decide to escalate from one number per fix:
- Fixed threshold reads trace(P);
- CA-TBL reads PCS, a monotone function of trace(P).

A learned estimate of the position error cannot carry more information than the error itself. So Fixed threshold,
itself a comparator, was given the **true** squared position error in place of trace(P), at four thresholds, in two
configurations, over 20 seeds.

**Result: no gain.**
- At the same threshold, 22 of the 24 paired intervals in Table 6 include 0.
- The other two are the same cell, endgame T = 12: availability +2.3 pp [+0.5, +4.0] at +0.91 J
  [+0.04, +1.83]. That is a trade of accuracy for energy, not a free gain. Two exclusions in 24 tests are also about
  what chance alone produces.
- The registered rule on the registered metrics reported MATERIAL energy headroom in the endgame. Both qualifying
  pairs, however, compare against a trace setting that another trace setting beats on accuracy and energy. Against
  the non-dominated trace settings, no oracle setting improves accuracy or energy. This check was made after
  scoring and is disclosed in the registration.

**Why.** The trigger is not limited by how well it knows the error. So no learned confidence input can move CA-TBL or
Fixed threshold beyond what choosing the threshold already gives.

## 2. A learned 868 MHz path-loss model (Table 7)

**Why real data.** In the simulator, RSSI is generated by the simulator's own path-loss model, so a model trained on
it can only relearn that model. The test therefore uses real 868 MHz measurements:
- 131 057 packets, 9 gateways, Bonn (Rademacher et al. 2021);
- evaluated on 1 km blocks never seen in training.

**Result for an RSSI-only localiser: a real gain.** This is the job of the LoRa-868 RSSI comparator.

| | log-distance inversion | gradient-boosted trees |
|---|---|---|
| range error, 68 % factor | ×/÷4.41 (global), ×/÷2.68 (per gateway) | ×/÷1.61 |
| position median error, 21 292 packets heard by ≥ 3 gateways | 2296 m (better inversion) | 1337 m |

ML minus the better inversion, in mean log10 position error: −0.197 [−0.241, −0.144].

**The gain is not from ML.** A per-gateway linear regression of log-distance on RSSI and SNR, three parameters per
gateway, matches it:
- ×/÷1.61 range factor and 1365 m median position error;
- ML minus linear: −0.0024 [−0.0085, +0.0040].

The improvement comes from regressing distance on RSSI instead of inverting RSSI on distance. That pulls each range
toward the distances seen in training, which is a prior. It holds only where deployment resembles the survey.

**Inversion is worse than no ranging.** Multilateration from inverted ranges is worse than taking the centroid of the
gateways that heard the packet (1652 m median).

**For CA-TBL:**
- Endgame accuracy comes from 2.4 GHz time of flight, which this does not touch.
- Whether a regression prior fitted elsewhere transfers to a rural search area is untested; it needs a survey of
  that area.
- The ML part is settled independently of the system: it adds nothing over the linear model.
