## The finding that re-scopes three items

**`EnginePhyProvider` models exactly one field node.** It is constructed with a single
`fieldNodeId` and carries a single `SetNodePosition()`. A frame originating from any
other node has no position it can place, so the link is never computed.

Measured, `nTags=2`, 600 s: the peer sent **162** `ESC_REQUEST`s, lost **zero** to the
duty governor, CAD, or collision — and **no anchor received one**.

The provider sits **below** the MAC, so no MAC-level work reaches it. The consequences:

- **C2-full is necessary but NOT sufficient.** Giving each tag its own policy, energy
  model and filter does not make the provider multi-node. `docs/WORK_PACKAGES.md` scopes
  C2 as a scenario-level refactor; it is not. **The provider must carry a position per
  node before any second target can be heard.**
- **C4 cannot be demonstrated** until that happens.
- **C5** inherits the same dependency: relayed ranging needs a relay whose transmissions
  propagate.
- **C3 is unaffected.** What it measured is the *measured* tag answering and correctly
  ignoring, and that path is modelled. Its result stands.

Full detail: `report/C4_PROVIDER_BLOCKER.md`.

## New latent defect, not yet biting

**The dedup cache cannot distinguish two nodes.** `CaTblMac::NextPacketId()` returns
`++m_packetIdCounter`, a per-MAC counter starting at 0, so every node emits packet ids
1, 2, 3… and `DeliverRx` keys its dedup cache on **packet id alone**. Two nodes' frames
therefore collide in that cache and the second is dropped as a duplicate.

`droppedDedup` measured **0** in the run above, so this is *not* what is currently
blocking C4 — the frames never arrive to be deduped. But it will bite the moment two
nodes genuinely transmit into the same cache, which is exactly what fixing the provider
enables. **Fix it in the same change**: key on `(originId, packetId)`, which is what a
flood dedup should use and what the neighbour-table comment already assumes.

admitted-but-unreachable peer it degrades the score for an **energy** defect rather than
