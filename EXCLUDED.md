# What this repository deliberately does not contain

Every exclusion below is a decision someone wrote down. `scripts/publication_ready.sh`
asserts that nothing with a source-code extension is being ignored outside these
paths, so an exclusion that arrives as a side effect of a `.gitignore` pattern
**fails the manifest** rather than passing silently.

That assertion exists because two such side effects were found on 2026-08-19:

- `.gitignore`'s unanchored `build/` matched a directory at *any* depth and hid
  `src/lorawan/.github/actions/build/action.yml`, a YAML source file. Fixed by
  anchoring to `/build/`.
- `scratch/.gitignore` was a WHITELIST (`/*` then `!*.cc`, `!*.py`) and hid 13 shell
  scripts and 2 markdown files, including the pipeline that regenerates the excluded
  results. Fixed by inverting it to a blacklist.

Neither was visible to any check. Both were found by comparing files on disk against
files in the index.

## Excluded, with reasons

| path | what it is | why excluded | how to regenerate |
|---|---|---|---|
| `build/`, `cmake-cache/` | ns-3 compiled objects, binaries, CMake state | build artefacts | `./ns3 configure --enable-examples --build-profile=optimized && ./ns3 build` |
| `results/**/trace_*.csv` | per-cycle simulation traces, ~13 GB | generated; the largest single category | `scripts/catbl_gates.sh`, `scripts/sweeps/*.sh` |
| `results/**` other outputs (~16 GB total) | sweep CSVs, plots, `.pkl` models, `.npy` splits, `stage2_result_M*.json` | generated by the pipeline scripts, which ARE shipped | `scratch/master_reset.sh`, `scratch/run_full_pipeline.sh` |
| `results/*/arm_summary.csv`, `run_id.txt` | **NOT excluded** — 1,065 sidecars are tracked | they are the provenance record; each carries a sha256 digest of the outputs its run produced | — |
| `audit/` | scratch directories from provenance audits | working state, superseded by `SESSION_CHANGELOG.md` | — |
| `testpy-output/` | ns-3 test-runner XML and pcap | generated by `./test.py` | `./test.py` |
| `src/lorawan/.git` | upstream git history of the vendored module | flattened deliberately; see the vendoring commit | `~/lorawan-upstream.bundle`, or clone `https://github.com/signetlabdei/lorawan` |
| `.lock-ns3_linux_build` | ns-3 build lock file | machine state | — |

## Deliberately KEPT despite looking generated

| path | why |
|---|---|
| `scratch/dataset_partial.csv` | 2.1 MB, 8,968 rows, simulation-shaped schema — but **no producer exists anywhere in the tree**. Classified by producer, not by suffix; with no producer found it is kept under keep-when-uncertain. Adding an ignore pattern on the strength of the word "partial" would be suffix-classification in different clothing. |
| `Untitled.java` | 63 KB, purpose unidentified, no producer found. Same rule. Kept so nobody later infers it is load-bearing. |
| `scratch/*.sh` (13 files) | the tooling that regenerates everything excluded above. Excluding 16 GB is only defensible while its generators ship. |
| `src/lorawan/**` (140 files) | third-party GPL module, vendored flat. Verified usable, not merely present: `scratch/lora-dataset.cc` includes `ns3/lorawan-module.h` and compiles. |

## The one credential in the tree

`utils/coverity-report.sh:66` contains `--form password=4jk2BVX9`. This is **upstream
ns-3 code**, already public in every ns-3 release, and is not a secret of this project.
It is left untouched: rewriting history over an upstream file would be a large,
irreversible operation to remove something that is not confidential.

`scripts/publication_ready.sh` reads the block below. A path prefix here is a
**reviewed** exclusion; anything ignored outside it that carries a source extension
fails the manifest. This block is the single source of truth — the script parses it
rather than keeping its own copy, so the two cannot drift.

```reviewed-exclusions
build/
cmake-cache/
results/
audit/
testpy-output/
src/lorawan/.git/

CA_TBL_SIMULATION_REPORT.md
SESSION_CHANGELOG.md
src/catbl-propagation-study/results/corpus.json
```

Three of those entries are **files, not directories**, and are deliberately ignored
rather than incidentally so. Gate **G8** asserts each stays untracked, and has a
negative fixture. Their reasons:

| path | why it is not tracked |
|---|---|
| `CA_TBL_HANDOFF_v4.md`, `CA_TBL_HANDOFF_v5.md`, `CA_TBL_HANDOFF_v6.md` | the working handoff and its predecessors; a project rule stated in 19 documents keeps it untracked. `35466c0` tracked it by a staging error and `aa8328b` untracked it |
| `SESSION_CHANGELOG.md` | working log, never a deliverable |
| `src/catbl-propagation-study/results/corpus.json` | the frozen realization corpus, 10.7 MB, deterministic from `corpus.py` at seed 20260819. Its `.sha256` is tracked as the provenance anchor and gate G11 verifies the file against it |
| `CA_TBL_SIMULATION_REPORT.md` | an earlier technical report. Zero `###` section overlap with `Simulation.md`, so not a draft of it; cited by no deliverable; entered the index only as a side effect of an `r80` one-liner. Annotated in its own header |

## Machine-local tool settings

Editor and tool settings directories are ignored through each clone's own `.git/info/exclude`,
not the tracked `.gitignore`: they are machine state, never published, and the repository
names no tool. `publication_ready.sh` judges only the tracked ignore rules.

## Redacted, not removed

One path segment in six sidecars, `report/b8/m{false,true}/s{1,2,3}/run_id.txt`, was replaced by
`[redacted]` on 2026-10-19 by owner decision. The redaction, its exact scope and the original blob ids
are recorded in `SHA_MAP.md` ("Six sidecars with one path segment redacted").

## Traces are excluded, and that exclusion is asserted

`trace_*.csv` is never tracked — roughly 13 GB across the corpus, and every one is
regenerable from its directory's `run_id.txt` invocation. `publication_ready.sh`
asserts **0 tracked**, and it caught 12 that `a0ccb4f` committed with `baseline_v7`
and `causal_v7`: that commit dropped `stdout.log` from the staged set but not the
traces. Untracked in the follow-up. Summaries and sidecars are tracked; traces are
not.

## Documents allowed to cite superseded evidence

`publication_ready.sh`'s dirty-provenance assertion asks whether a reader can regenerate a
cited result. One document cites superseded campaigns **on purpose**: it documents what
those runs produced, so repointing it would attach its descriptions to numbers they did not
generate. Its citations are correct for what it documents and must not move.

Enumerated **by path**, with a reason each. This is not a blanket exemption: any other
document citing a dirty source still fails the assertion.

| document | reason |
|---|---|
| `report/REPORT_DATA_PACK.md` | a record of what each historical campaign produced, including the superseded `results/causal`, `det_a`, `det_b`, `p10_plane`, `p10_plane_fix`. Repointing it to `baseline_v7` would describe one run's output under another run's path |

```reviewed-dirty-citations
report/REPORT_DATA_PACK.md
```
